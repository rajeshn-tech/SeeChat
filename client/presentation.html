BACKGROUND & OBJECTIVE
Slide 2 / 8

Why Desk Ping Was Built

Solving communication challenges in production environments.

❌

Before Desk Ping

  • Artists frequently missed important production messages.
  • External communication tools were not suitable for confidential production workflows.
  • Linux and Windows users lacked a unified internal communication platform.
  • Communication history was not consistently available for future reference.
✅

The Desk Ping Solution

  • Browser-based messaging accessible from connected workstations.
  • Internal text-only communication without file sharing.
  • Lightweight visual notifications designed to reduce workflow interruptions.
  • Structured audit records containing timestamps, senders, and recipients.
TECHNICAL ARCHITECTURE
Slide 3 / 8

System Architecture

Lightweight, real-time architecture designed for secure local networks.

🐍

Real-Time Python Server

The Flask-SocketIO backend manages real-time messaging, active user sessions, and connected workstations across the local network.

💻

Cross-Platform Web Client

The browser-based interface is accessible from Windows and Linux workstations without requiring separate desktop installation.

📁

Local Storage & Audit Logs

SQLite stores application data locally, while timestamped CSV logs provide accessible records for reporting and auditing.

ACCOUNTABILITY & AUDIT
Slide 6 / 8

Secure Audit Trail

Every message is linked to an authenticated user and recorded for future auditing.

Security Verification & Logging Flow

Step 1: User authenticates using authorized production credentials.

Step 2: Every message is automatically tagged with Timestamp, Sender, Recipient / Group, and Workstation IP.

Step 3: The audit record is automatically written to backend CSV logs.
